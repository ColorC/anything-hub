# 仓库接入范围

启动器接收公开 Git 仓库地址，在运行启动器的电脑上下载源码、读取项目说明与许可、构建网页输出并打开游戏。添加作品不需要编辑启动器源码或内置目录。已添加的目录保存在该电脑的 `runtime/catalog.json`，安装版本采用 Git commit。

支持的仓库主页来自 GitHub、Gitee、GitLab、Codeberg，使用 HTTPS，不含登录凭据。主页地址与对应 `.git` 地址指向同一来源。可选择分支或标签。这个 URL 支持范围不代表所有这些网站在每个网络环境中都能访问。

## HTML5 静态输出

项目入口是 `index.html`，随仓库包含 HTML、JavaScript、CSS 和运行所需的本地资源。资源使用相对地址，不能依赖目录之外的文件。没有需要先执行的构建脚本。入口不在仓库根目录时，在添加作品的高级选项中指定相对入口目录。

这沿用 [itch.io HTML5 作品的入口与相对资源约定](https://itch.io/docs/creators/html5)，但作品下载到本机，不上传到 itch.io，也不要求创建 itch.io 账户。本版接收 Git 源码，尚未接收 itch.io ZIP 包或 GitHub Release 资产。

## npm 网页构建

仓库根目录包含 `package.json`、`package-lock.json`，并定义 `scripts.build`。启动器在本机执行：

```sh
npm ci --no-audit --no-fund
npm run build
```

构建输出应是带相对资源地址的静态网页。默认寻找 `dist/index.html` 或 `build/index.html`；其它输出目录可通过高级选项指定。存在构建脚本时，不能把尚未构建的根 `index.html` 当成已经可玩的作品。

[npm 的 scripts 机制](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#scripts)是现有的构建入口；`dist`、`build` 和静态输出是本启动器支持的项目约定，不是所有 npm 包的通用要求。需要后端服务、数据库、开发服务器、原生执行文件或其它构建工具的仓库不属于本版的安装范围。

## 许可与失败处理

作品详情保留仓库链接、项目说明、实际许可文件及下载版本。找不到许可声明时显示“未声明”，不能仅凭公开仓库地址认定作品是开源。仓库许可不等于所有依赖的许可都已经逐项检查。

下载、依赖安装、构建或入口检查失败时保留已有源码与日志，可以从作品详情重试或保存问题报告。构建脚本由本机 Node/npm 执行，当前没有提供构建沙箱。

路径必须留在作品的源码目录内。隐藏目录、目录穿越、指向其它目录的链接和硬链接不作为网页文件对外提供。报告使用实际本地安装的 Git commit，不能由浏览器提交的版本替代。

入口检查仅将 `icon`、`shortcut icon`、`apple-touch-icon`、`apple-touch-icon-precomposed`、`mask-icon` 的缺失图标视为可选资源；它们仍须通过相对路径、目录边界、隐藏文件及链接检查。通过检查的缺失图标引用只从打开时的 HTML 中移除，仓库与构建输出保持原样。脚本、样式、预加载、manifest 和图片等其它缺失资源仍使安装失败。GNU 许可类别与版本依据实际许可文件的标题及紧邻版本行识别，避免正文引用其它许可证时误判。

HTML 中自动加载的外部 HTTP(S) 资源（包括外部图标）沿用本机隔离政策，只从响应页面中移除，并保留外部主机诊断；它们不计入缺失本地图标。原仓库与构建输出不变，依赖外部服务的项目不保证兼容。

## 接入操作

打开“添加仓库”，粘贴仓库主页地址，点击“添加并安装”。作品进入目录后可以打开详情，查看来源和许可；安装结束后点击开始游戏。关闭并重新启动中心后，已添加的作品和安装状态继续保留在这台电脑。

内置的 2048 与 Hello 猜单词用于初次体验；它们与后来添加的作品通过同一安装流程运行。GitHub 上的 2048、Hello 与 Hextris 已在 Windows 上验证下载、安装和浏览器操作，其中 Hello 执行了 npm 依赖安装与构建。Gitee、GitLab、Codeberg 目前验证了仓库 URL 规则与本地测试夹具，尚未验证这些站点的实际联网下载。其它操作系统的原生启动和构建也尚未验证。
